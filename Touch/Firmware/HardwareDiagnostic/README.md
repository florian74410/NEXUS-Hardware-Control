# Hardware Diagnostic 0.0.3 DEV
Separate experimental sketch; SerialDiagnostic remains rollback. ESP32 Arduino 3.2.0, ArduinoJson 7, TFT_eSPI configured for Freenove FNK0114S 4-inch ST7796 with touch (official vendor library). 240 MHz, no radio initialization. Core 0 serial + active-low RGB (22/16/17); core 1 LCD/touch. Bounded mailbox. First boot calibrates touch via TFT_eSPI and saves only calibration in NVS. Existing hello/ping protocol compatible. Green means recent request (<5s), red means no recent request after prior contact, blue waiting; CLI ping is one shot not persistent connection. Actual heap and minimum heap, uptime, packet count, task core IDs, UI update rate and draw time. UI update rate is not theoretical panel FPS; per-core CPU load not implemented (no fake values). Direct TFT primitives for bring-up, no LVGL or full framebuffer yet. Source uncompiled and untested at publication.
Vendor: https://docs.freenove.com/projects/fnk0103/en/latest/ ; https://github.com/Freenove/Freenove_ESP32_Display/tree/main/Libraries/FNK0114S_4.0inch_ST7796

## 0.0.4 Graphics Alpha
Reusable dirty-region renderer caches text/color, with one 448x32 RGB565 sprite (28672 bytes of pixel data plus overhead) and direct-render fallback if allocation fails. UI task owns display and sprite. Calibration key cal-v2 forces a fresh calibration on first boot of this release; CALIBRATE button repeats it and stores parameters in NVS. UI updates/s counts changed render passes, not panel FPS. No SPI or partition changes. Compile/hardware validation pending.
